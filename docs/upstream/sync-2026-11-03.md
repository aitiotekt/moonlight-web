## 哪些已经官方支持，哪些继续维护

下表同时核对了 v0.4.1 与上述 main 的实际代码。两者之间没有修改
`ClipboardBridge.cpp/.h`，不能把发布说明中的“键盘支持”理解为覆盖了所有 fork 功能。

| 能力 | 官方 v0.4.1 / 最新 main | 本次处理 |
|---|---|---|
| 浏览器向同机 Sunshine 粘贴文本、主机文本回传浏览器 | 已有 `clipboardcaps`、`clipboardpaste`、`clipboard` 与 `ClipboardBridge`；原基线也已有 | 复用官方桥接和三个传输，不维护另一套基础实现 |
| 内建 native host 的剪贴板可用性 | 官方按 `activeAddress` 判断同机；native host 没有网络地址，未单独放行 | 保留 `MediaType::NativeHost` 的显式可用性判断，同时保留受限会话的权限门禁 |
| macOS 主机后台复制和粘贴 | 官方依赖 `QClipboard::dataChanged`，粘贴注入固定 Ctrl+V | 保留 `NSPasteboard` changeCount 轮询和 Cmd+V；只在有接收订阅时启动 250 ms 轮询 |
| 会话级剪贴板开关、发送/接收分开、重新连接先关闭再协商 | 官方没有 `clipboardconfig` 协议和方向状态 | 保留 `ClipboardPolicy::SessionSettings`，覆盖 DataChannel、MediaTrack 和 WSS，接收关闭后也拦截已排队通知 |
| 手动发送文本、浏览器写剪贴板失败时手动复制 | 官方基础桥接不提供本 fork 的设置面板 | 保留输入设置面板和手动操作 |
| 键盘布局、Option/AltGr、死键、移动端文字、锁定键、断流松键 | 官方已有，而且此次上游显著改进 | 采用上游实现，不以旧 fork 的键盘逻辑覆盖它；保留右 Alt 的 `VK_RMENU=0xA5` |
| 任意物理键重映射/忽略，例如 AltLeft ↔ MetaLeft | 官方的 `keyboard_layout_fidelity` 是字符/位置策略，不是自定义键到键映射 | 保留 `SessionKeyMapper`、映射编辑器、修饰键和心跳转换 |
| 每主机可选记忆、会话切换与重连继承 | 官方没有本 fork 的输入偏好结构 | 保留 `mw-session-input:owner\|guest:<uuid>`，不存剪贴板内容 |
| 手柄按钮/轴重映射 | 官方 v0.4.1 已支持 `GamepadRemapDialog` 和 `mw-gamepad-mappings` | 使用官方功能；与键盘映射并存 |

剪贴板仍仅支持文本，最多 262,144 个 UTF-16 单元；不支持图片/文件，也没有
把远端 Sunshine/Apollo 主机的系统剪贴板接入后端。继续沿用原权限范围，
没有为受限邀请会话新增读取主机剪贴板的权限。

## 同步带来的主要变化

v0.4.1 包括 MWSR 默认上采样、Auto 编解码选择、HDR 修正、键盘布局与 AltGr
修正、崩溃自动重连、ICE-TCP 网络回退、显示器与无鼠标主机处理，以及官方
入口的界面完整性验证。完整清单见上面的官方发布说明。

正式版之后的 97 个提交也已合并，包括 MWSR 后续优化、麦克风选择与静音提示、
按浏览器/主机记录的 Auto 能力观测，以及设置预览和统计等改进；以合并的
`upstream/main` 为准，不单独挑选这些改动。

合并额外处理了这些输入兼容点：

- 输入设置弹窗与官方手柄映射弹窗都拦截本地按键，避免输入泄漏到主机。
- 重映射后清除原键的字符、死键和 AltGr 元数据，避免上游把目标键吞掉或解释为原字符。
- 未配置映射时保留上游布局/AltGr 行为；映射 Ctrl 或右 Alt 时不执行原物理 Ctrl 的 AltGr 补偿释放。
- 上游吞掉晚到的松键时，同步清除映射器的已按下状态。
- 独立后端测试项目补上 macOS `HostAppImageMac.mm`，修正上游新增图片测试的链接缺口。
- 静态资源根目录与请求文件统一使用规范路径，修正 macOS `/var` → `/private/var`
  及根目录符号链接导致的误拒绝；继续拒绝越界文件符号链接。
- Windows 启动器路径辅助函数显式使用 Windows 分隔符，让跨平台纯逻辑测试保持相同语义。
- 保活 ping 不再重置尚未收到 pong 的超时计时器，修正相同定时间隔时 Qt 6.12
  可能持续推迟掉线检测的问题；独立后端测试中的无应答服务器用例覆盖此路径。

## 构建与验证

本机使用 arm64 Release、Qt 6.12.0 和 Homebrew OpenSSL 3.5.9。

```sh
cmake -S backend -B build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_OSX_ARCHITECTURES=arm64 -DMW_VERSION=0.4.1.97 -DMW_EDITION=prod
cmake --build build -j 8
ctest --test-dir build --output-on-failure
cd frontend
NODE_OPTIONS=--no-experimental-webstorage npm test
npm run check
```

本机 Node 26 默认暴露的 Web Storage 与 jsdom 不兼容；测试命令使用上述环境
开关，交由 jsdom 提供 localStorage，不改浏览器产品逻辑。

- 前端：202 个文件、2,257 项测试通过；包含 fork 输入/剪贴板测试和新增合并回归。
- 前端格式、ESLint、三语 i18n（1,134 个键）通过。
- 主构建 CTest：security-tnr、native-host、native-host-boundary 全部通过。
  security-tnr 43,737 项检查、native-host 10,717 项检查通过；不适用于本机的平台/
  设备用例按上游逻辑跳过，不能视为 Windows/Linux 真机串流验证。
- 独立后端项目：backend-tnr 17,934 项检查全部通过；ice-tcp-passive 通过。
  可用 `cmake -S backend/tests -B build/backend-tests -G Ninja`、
  `cmake --build build/backend-tests` 和
  `ctest --test-dir build/backend-tests --output-on-failure` 复现。

打包脚本 `scripts/package-macos-local.sh` 从当前构建生成独立 `.app`、`.pkg`、
便携 `.zip`、源修订记录和 `SHA256SUMS`，不安装或替换运行中的应用。
可通过 `SIGN_IDENTITY` 传入本地签名身份；默认使用 ad-hoc 签名。
脚本检查动态库可重定位性，并从所有实际携带的 Mach-O 文件计算最低 macOS。
本机 OpenSSL 要求 **macOS 27.0**，所以本地产物也要求 27.0；它不继承官方
安装包的旧系统兼容承诺。要支持更旧系统，需使用兼容部署目标重建依赖。

## 访问方式限制

v0.4.1 起，官方公共入口 `stream.moonlightweb.top` 对照官方清单校验界面文件，
拒绝修改版及未知正式版本。这份包含新模块的 fork **不能使用官方生产入口加载**。
直接通过本机/LAN HTTPS 地址或自有域名访问本机服务器所提供的界面。
本次未改动或绕过官方完整性验证，也未替 fork 部署公共入口。

代码依据：`bootstrap/v1/official.js` 的 `PRODUCTION_ENFORCES` / `interfacePolicy`，
以及 `bootstrap/v1/boot.js` 的 `officialCheck` 和文件摘要校验。
